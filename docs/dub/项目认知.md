# 先建立一个总认知

Dub 是一个“链接归因平台”，不只是短链工具。它把几件事放在一起做：

- 短链管理：创建、编辑、分组、打标签、自定义域名
- 流量分析：点击、来源、事件、客户
- 转化跟踪：lead、sale、revenue 归因到某条链接
- 联盟/推荐计划：Partner Program

## 什么是链接归因

“链接归因平台”这几个字可以拆成两部分：

- 链接：就是你发出去的那个网址，通常会被缩短成短链
- 归因：就是“结果到底该算到谁头上、哪条链接头上、哪个渠道头上”

最简单的例子：

你们公司做了一次推广，同一个商品页面会被很多地方分享：

- 小红书博主发了一条链接
- 微信公众号发了一条链接
- 广告投放落地页放了一条链接
- 邮件营销里也放了一条链接

如果所有地方都直接放同一个原始网址，最后你只能看到“总共有一些人访问了页面”，但你
很难准确回答：

- 哪个渠道带来的点击最多？
- 哪个渠道真正带来了注册？
- 哪个渠道最后带来了付费？
- 某个合作伙伴值不值得继续合作？

Dub 这种产品就是用来解决这个问题的。
你可以把它理解成一套“可追踪的链接系统”：

1. 先把原始长链接变成短链
   比如把一个很长的商品页地址，变成 dub.sh/abc123
2. 给不同渠道生成不同链接
   虽然都跳到同一个商品页，但每个渠道拿到的是不同短链

- 博主 A: dub.sh/a1
- 广告 B: dub.sh/b1
- 邮件 C: dub.sh/c1

3. 用户点击时，系统记录这次访问
   它会记下很多信息，比如：

- 点了哪条短链
- 什么时间点的
- 来自哪个国家/地区
- 什么设备
- 来源渠道

4. 如果用户后来注册、下单、成交
   系统再把这个结果“归到”前面那条链接上

于是你就能知道：

- dub.sh/a1 带来了 100 次点击，20 个注册，5 个付费
- dub.sh/b1 带来了 300 次点击，但只有 1 个付费
- dub.sh/c1 点击少，但成交率高

这就叫“归因”。
所以 Dub 不是单纯的“短网址网站”，而是：

- 用短链作为入口
- 用追踪记录用户点击
- 用分析把结果归到具体链接/渠道
- 再把这些数据用于营销、增长、联盟分销

  - 如果你要验证最基础的 tracking，至少还要补 Redis
  - 如果你要看到 Analytics/Events 这类分析结果，还要补 Tinybird
