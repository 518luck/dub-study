# Dub 本地启动

这份文档只解决一件事：把当前仓库在本地跑起来。

## 1. 环境要求

- `node v23.11.0`
- `pnpm 9.15.9`
- `docker` / `docker-compose`

根仓库 `README.md` 当前也是这组推荐版本。

## 2. 安装依赖

在仓库根目录执行：

```bash
pnpm install
```

## 3. 准备环境变量

复制一份 web 应用环境变量模板：

```bash
cp apps/web/.env.example apps/web/.env
```

先优先确认下面这些值。

### 最小必配

- `NEXT_PUBLIC_APP_NAME=Dub`
- `NEXT_PUBLIC_APP_DOMAIN=dub.co`
- `NEXT_PUBLIC_APP_SHORT_DOMAIN=dub.sh`
- `DATABASE_URL="mysql://root:@localhost:3306/planetscale"`
- `PLANETSCALE_DATABASE_URL="http://root:unused@localhost:3900/planetscale"`
- `NEXTAUTH_SECRET=自己生成一个随机字符串`
- `NEXTAUTH_URL=http://localhost:8888`

### 建议尽早配置

这些不一定阻止首页启动，但很多功能会依赖它们：

- `UPSTASH_REDIS_REST_URL`
- `UPSTASH_REDIS_REST_TOKEN`
- `QSTASH_TOKEN`
- `QSTASH_CURRENT_SIGNING_KEY`
- `QSTASH_NEXT_SIGNING_KEY`
- `TINYBIRD_API_KEY`
- `TINYBIRD_API_URL`
- `RESEND_API_KEY` 或本地 SMTP

## 4. 启动本地依赖服务

仓库已经提供了本地开发用的依赖服务配置：

- MySQL: `3306`
- PlanetScale HTTP 模拟代理: `3900`
- MailHog: `1025` / `8025`

启动：

```bash
docker-compose -f apps/web/docker-compose.yml up -d
```

如果你只想先验证邮件链路，也可以单独起 `mailhog`，但正常本地启动建议全部拉起。

## 5. 推 Prisma 表结构

进入 web 应用目录后执行：

```bash
cd apps/web
pnpm prisma:push
```

这一步会做两件事：

- 根据 Prisma schema 生成 Prisma Client
- 把当前 schema 推到本地数据库

如果你看到类似 “table does not exist” 的错误，通常就是这一步没做。

## 6. 启动开发环境

在 `apps/web` 目录执行：

```bash
pnpm dev
```

当前脚本会同时启动：

- Next.js 开发服务器，端口 `8888`
- Prisma Studio

默认访问地址：

- `http://localhost:8888`

## 7. 本地域名说明

这个项目的 middleware 会按域名分流，所以除了 `localhost:8888`，你后面还可能会用到：

- `http://app.localhost:8888`
- `http://partners.localhost:8888`

现代系统通常会把 `*.localhost` 解析到本机。

如果你的环境不认，再考虑补 `hosts`。

## 8. 完整功能依赖

如果你的目标不是“页面先跑起来”，而是“主要功能都可用”，还要继续补这些外部服务：

- Upstash Redis (可以在边缘网络（Edge）直接调用的 Redis 服务。)
- Upstash QStash
- Tinybird (把你的数据变成实时的分析型 API。)
- Resend 或 SMTP
- Stripe
- OAuth providers（Google / GitHub / Framer）
- Vercel Domains API
- 其他 `.env.example` 里的第三方平台变量

这些缺失时，常见表现是：

- 某些接口 500
- 登录方式缺失
- 支付/计费页面不可用
- 邮件不发送
- cron / webhook / 队列功能不可用

## 9. 常用命令

在 `apps/web` 目录下：

```bash
pnpm dev
pnpm prisma:push
pnpm prisma:studio
pnpm prisma:generate
```

在仓库根目录：

```bash
pnpm install
pnpm dev
pnpm build
```

## 10. 常见问题

### 数据表不存在

执行：

```bash
cd apps/web
pnpm prisma:push
```

### 本地邮件看不到

确认：

- MailHog 已启动
- `SMTP_HOST=localhost`
- `SMTP_PORT=1025`
- 本地调试时不要误配真实 `RESEND_API_KEY`

MailHog 面板：

- `http://localhost:8025`

### 端口冲突

这个项目默认会占用：

- `8888`：Next dev
- `3306`：MySQL
- `3900`：PlanetScale HTTP 代理
- `1025` / `8025`：MailHog

### 页面能开，但功能到处报错

优先检查：

- `apps/web/.env`
- Redis 相关变量
- Tinybird 相关变量
- Stripe / Resend / OAuth 相关变量

## 11. 最短启动路径

如果你只想最快看到页面：

```bash
pnpm install
cp apps/web/.env.example apps/web/.env
docker-compose -f apps/web/docker-compose.yml up -d
cd apps/web
pnpm prisma:push
pnpm dev
```

然后打开：

```txt
http://localhost:8888
```
