# React Email 从零到上手完全指南

---

## 一、React Email 到底是什么？

### 1.1 一句话概括

React Email 是一个**用 React 组件写邮件模板**的工具。你用 JSX 写邮件界面，它帮你编译成纯 HTML（兼容 Gmail、Outlook 等所有邮箱客户端）。

### 1.2 它和 Ant Design 有什么不同？

Ant Design 是你**在浏览器里看到的网页 UI 组件库**（按钮、表格、弹窗），运行在浏览器里。

React Email **不是一个在浏览器里显示的 UI 库**，它包含两样东西：

| 部分 | 说明 | 类比 |
|------|------|------|
| **组件库** `@react-email/components` | 写邮件模板用的组件（Html、Body、Button 等） | 类似 antd 的 `<Button>`，但渲染目标是邮件 HTML |
| **开发预览服务器** `email dev` | 在本地起一个后台页面，实时预览你写的邮件 | **这就是你说的"后台地址"**，类似一个专属的邮件预览工具 |

> **核心区别**：antd 组件运行在你的 Next.js 应用中，用户在浏览器看到。React Email 组件**不直接给用户看**，而是编译成 HTML 字符串，再通过 Resend/SMTP 等服务发送到用户的邮箱。开发时用 `email dev` 起一个本地预览服务器来查看邮件效果。

### 1.3 为什么需要专门的邮件组件？

写邮件和写网页**完全不同**：
- 邮件不支持 CSS Grid、Flexbox
- 邮件只能用 `<table>` 布局
- 邮件需要内联样式，不能用外部 CSS
- 每个邮箱客户端（Gmail vs Outlook vs Apple Mail）渲染差异巨大

React Email 的组件帮你自动处理这些兼容性问题，底层全部转成 `<table>` 布局 + 内联样式。

## 二、快速开始（在已有的 Next.js 项目中集成）

### ⚠️ 重要：不要用 `create-email` 创建新项目

```bash
# ❌ 这个是错的！它会创建一个全新的独立项目，脱离你的 Next.js 项目：
pnpm create email
npx create-email@latest

# ✅ 正确做法：在你的 Next.js 项目中直接安装包：
pnpm add @react-email/components react-email
```

`create-email` 会生成一个名叫 `react-email-starter` 的**独立目录**，只是为了让你体验 React Email 本身。**在已有的 Next.js 项目中用 React Email，只需要安装两个 npm 包就够了**，不需要新建项目。

### 2.1 安装依赖

看看本项目的 `packages/email/package.json`，已经安装了核心依赖：

```json
{
  "dependencies": {
    "@react-email/components": "^1.0.8",  // 邮件组件库（Html、Button、Tailwind 等）
    "react-email": "^5.2.8",               // CLI 工具 + render 渲染功能
    "resend": "6.6.0"                       // Resend 发送 SDK
  }
}
```

三个包的职责：

| 包名 | 做什么 | 何时用 |
|------|--------|--------|
| `@react-email/components` | 提供 Html、Button、Tailwind 等邮件组件 | **写邮件模板时** |
| `react-email` | 提供 `email dev` CLI 和 `render()` 渲染函数 | **开发预览 + 发送前转 HTML** |
| `resend` | 调用 Resend API 发送邮件 | **实际发送邮件时** |

### 2.2 已有 Next.js 项目集成步骤（纯手动，无需 create-email）

如果你在一个全新的 Next.js 项目中要加入 React Email，只需 3 步：

**第 1 步：安装包**

```bash
pnpm add @react-email/components react-email @react-email/render
```

**第 2 步：在 package.json 加开发脚本**

```json
{
  "scripts": {
    "email:dev": "email dev --dir ./emails"
  }
}
```

- `--dir ./emails`：邮件模板放在 `emails/` 目录下（可以是任意路径，建议放在 src/emails）
- 端口默认 3000，加 `-p 3333` 可自定义

**第 3 步：创建第一个邮件模板**

```
my-nextjs-app/
├── emails/               ← 新建这个目录
│   └── welcome.tsx       ← 写邮件模板
├── app/
├── package.json
```

模板内容：

```tsx
// emails/welcome.tsx
import { Html, Body, Container, Text, Heading } from "@react-email/components";

export default function WelcomeEmail({ name }: { name: string }) {
  return (
    <Html>
      <Body>
        <Container>
          <Heading>欢迎注册，{name}！</Heading>
          <Text>感谢你加入我们。</Text>
        </Container>
      </Body>
    </Html>
  );
}
```

跑起来：`pnpm email:dev`，打开 `http://localhost:3000` 看效果。

然后在 Next.js 的 API Route / Server Action 中这样发送：

```tsx
// app/api/send-email/route.ts
import { Resend } from "resend";
import WelcomeEmail from "@/emails/welcome";

const resend = new Resend(process.env.RESEND_API_KEY);

export async function POST() {
  await resend.emails.send({
    from: "system@myapp.com",
    to: "user@gmail.com",
    subject: "欢迎",
    react: <WelcomeEmail name="张三" />,
  });
}
```

> **重点**：`create-email` 创建的独立项目适合学习体验，真实项目就是安装包 + 建 emails 目录 + 加 dev 脚本。

### 2.3 本项目（dub）已有的配置

在我们的 dub 项目中，email 包已经配好了开发脚本：

```json
// packages/email/package.json
{
  "scripts": {
    "dev": "email dev --dir ./src/templates -p 3333"
  }
}
```

- `--dir ./src/templates`：指定邮件模板放在 `src/templates` 目录下
- `-p 3333`：预览服务器跑在 3333 端口

跑起来：
```bash
cd packages/email
npm run dev
# 打开 http://localhost:3333
```

## 三、开发预览服务器（"后台地址"详解）

### 3.1 这就是你说的"后台地址"

运行 `email dev` 后，浏览器打开 `http://localhost:3333`，你会看到一个**邮件预览管理界面**：

- **左侧边栏**：列出 `src/templates` 下所有邮件模板文件，点击切换预览
- **右侧主区域**：桌面版 + 手机版双栏实时预览，修改模板代码后自动刷新
- **顶部工具栏**：切换暗色模式、查看 HTML 源码、复制等
- **底部 Resend 栏**：如果登录了 Resend，可以一键上传模板到 Resend 后台

这就是 React Email 和 antd 最大的区别——**它自带一个开发用的后台界面**，专门用来预览邮件效果。

### 3.2 哪些文件会出现在侧边栏？

React Email 用两个规则自动识别邮件模板：

1. 文件扩展名是 `.js`、`.jsx` 或 `.tsx`
2. 文件包含 `export default`（导出一个 React 组件）

比如 `verify-email.tsx`：
```tsx
export default function VerifyEmail({ email, code }) {
  return <Html>...</Html>;
}
```

只要满足这两个条件，就会出现在侧边栏。

### 3.3 如何隐藏不想显示的目录/文件？

目录名前面加下划线 `_` 即可隐藏：

```
src/templates/
├── _components/        ← 不会被扫描，不显示在侧边栏
│   └── my-button.tsx
├── verify-email.tsx    ← 会显示在侧边栏
└── welcome-email.tsx   ← 会显示在侧边栏
```

本项目中 `src/components/footer.tsx` 不属于 templates 目录，所以不会出现在侧边栏。

### 3.4 如何在预览时传自定义 props？

在邮件模板上加一个静态属性 `PreviewProps`：

```tsx
export default function WelcomeEmail({ userName, link }: { userName: string; link: string }) {
  return (
    <Html>
      <Text>你好 {userName}，点击下方链接确认注册：</Text>
      <Button href={link}>确认注册</Button>
    </Html>
  );
}

// 预览服务器会用这个数据渲染
WelcomeEmail.PreviewProps = {
  userName: "张三",
  link: "https://example.com/confirm?token=abc123",
};
```

### 3.5 静态资源（图片）怎么在预览中显示？

在 `emails` 目录下创建 `static` 文件夹（按 `--dir` 参数调整路径），比如：

```
src/templates/
├── static/
│   └── logo.png        ← 通过 /static/logo.png 访问
├── verify-email.tsx
```

模板中引用：
```tsx
<Img src="/static/logo.png" alt="Logo" />
```

> **注意**：这只是开发预览时有效。实际发送时图片需要托管在 CDN 上，用绝对 URL。

## 四、写邮件模板

### 4.1 基本骨架

一个邮件模板的最小结构：

```tsx
import {
  Html,
  Head,
  Body,
  Container,
  Text,
  Preview,
} from "@react-email/components";

export default function MyEmail({ name }: { name: string }) {
  return (
    <Html>
      <Head />
      <Preview>这是一封测试邮件</Preview>
      <Body>
        <Container>
          <Text>你好，{name}！</Text>
          <Text>这是邮件正文内容。</Text>
        </Container>
      </Body>
    </Html>
  );
}
```

### 4.2 常用组件一览

| 组件 | 相当于 HTML | 说明 |
|------|------------|------|
| `<Html>` | `<html>` | 邮件根元素 |
| `<Head>` | `<head>` | 放 style、meta 等 |
| `<Body>` | `<body>` | 邮件主体 |
| `<Preview>` | 不可见文本 | 收件箱里标题下方的预览文字 |
| `<Container>` | `<table>` 居中容器 | 内容居中，设最大宽度 |
| `<Section>` | `<table>` | 区块容器 |
| `<Row>` | `<tr>` | 行，配合 Column 用 |
| `<Column>` | `<td>` | 列，配合 Row 用，实现多列布局 |
| `<Heading>` | `<h1>-<h6>` | 标题 |
| `<Text>` | `<p>` | 段落文本 |
| `<Link>` | `<a>` | 链接 |
| `<Img>` | `<img>` | 图片 |
| `<Button>` | `<a>` 样式化成按钮 | CTA 按钮 |
| `<Hr>` | `<hr>` | 分隔线 |
| `<Tailwind>` | 无对应 | Tailwind CSS 包裹器 |

### 4.3 使用 Tailwind CSS

React Email 内置支持 Tailwind CSS（当前版本 tailwindcss 4.1.12）：

```tsx
import { Tailwind, Button, Text } from "@react-email/components";

export default function StyledEmail() {
  return (
    <Tailwind>
      <Text className="text-base text-gray-700">
        这是用 Tailwind 写的段落
      </Text>
      <Button
        href="https://example.com"
        className="bg-blue-600 text-white px-5 py-3 rounded"
      >
        点击这里
      </Button>
    </Tailwind>
  );
}
```

> **重要提示**：`<Tailwind>` 组件会把 Tailwind 类名**编译成内联样式**（因为邮件只认内联样式）。它的作用就是把 `className="text-base"` 自动转成 `style="font-size: 16px"`，开发时写 Tailwind，发送时变成内联样式。

#### Tailwind 自定义主题

```tsx
<Tailwind
  config={{
    theme: {
      extend: {
        colors: {
          brand: "#007291",
        },
      },
    },
  }}
>
  <Button className="bg-brand text-white px-4 py-2">
    自定义品牌色按钮
  </Button>
</Tailwind>
```

### 4.4 实战例子：本项目中的 verify-email.tsx

```tsx
// packages/email/src/templates/verify-email.tsx
import {
  Body,
  Container,
  Head,
  Heading,
  Html,
  Img,
  Preview,
  Section,
  Tailwind,
  Text,
} from "@react-email/components";
import { Footer } from "../components/footer";

export default function VerifyEmail({
  email = "panic@thedis.co",
  code = "123456",
}: {
  email: string;
  code: string;
}) {
  return (
    <Html>
      <Head />
      <Preview>Your Dub Verification Code</Preview>
      <Tailwind>
        <Body className="mx-auto my-auto bg-white font-sans">
          <Container className="mx-auto my-10 max-w-[600px] rounded border border-neutral-200 px-10 py-5">
            <Section className="mt-8">
              <Img src={DUB_WORDMARK} height="32" alt="Dub" />
            </Section>
            <Heading className="mx-0 my-7 p-0 text-xl font-medium text-black">
              Please confirm your email address
            </Heading>
            <Text className="text-sm leading-6">
              Enter this code on the Dub verify page to complete your sign up:
            </Text>
            <Section className="my-8 rounded-lg border border-neutral-200">
              <div className="mx-auto w-fit px-6 py-3 text-center font-mono text-2xl font-semibold tracking-[0.25em]">
                {code}
              </div>
            </Section>
            <Text className="text-sm leading-6 text-black">
              This code expires in 10 minutes.
            </Text>
            <Footer email={email} />
          </Container>
        </Body>
      </Tailwind>
    </Html>
  );
}
```

关键点：
1. `<Html>` 在最外层包装整个邮件
2. `<Preview>` 是收件箱里的预览文字
3. `<Tailwind>` 包裹可以使用 Tailwind CSS 类名
4. `<Container>` 负责居中 + 最大宽度，里面用 Section 分区
5. `<Footer>` 是复用组件（从 `../components/footer` 引入）

## 五、发送邮件

### 5.1 三种方式

| 方式 | 说明 | 适用场景 |
|------|------|----------|
| **Resend（推荐）** | `resend` 包直接传 React 组件，自动转 HTML | 生产环境，最简单 |
| **render + 任意服务** | 用 `render()` 把组件转 HTML，再给 Nodemailer/SendGrid 等 | 不想绑定 Resend |
| **email export** | CLI 命令一次性导出全部模板的 HTML 文件 | 非 JS 后端、手动模板化 |

### 5.2 方式一：直接用 Resend 发送（本项目的方式）

```tsx
import { Resend } from "resend";
import VerifyEmail from "./templates/verify-email";

const resend = new Resend(process.env.RESEND_API_KEY);

// Resend 支持直接传 React 组件，内部自动 render 成 HTML
await resend.emails.send({
  from: "My App <system@myapp.com>",
  to: "user@gmail.com",
  subject: "验证你的邮箱",
  react: <VerifyEmail email="user@gmail.com" code="123456" />,
});
```

> **优势**：不用手动 `render()`，Resend 内部自动处理。这就是你们项目中 `send-via-resend.ts` 做的事。

### 5.3 方式二：手动 render + 任意发信服务

```tsx
import { render } from "@react-email/render";
import nodemailer from "nodemailer";
import VerifyEmail from "./templates/verify-email";

// 1. 把 React 组件转成 HTML 字符串
const html = await render(<VerifyEmail email="test@test.com" code="123456" />);

// 2. 用任意发信服务发送（这里以 Nodemailer 为例）
const transporter = nodemailer.createTransport({ /* SMTP 配置 */ });
await transporter.sendMail({
  from: "noreply@myapp.com",
  to: "user@gmail.com",
  subject: "验证你的邮箱",
  html,  // 传入渲染好的 HTML
});
```

### 5.4 纯文本版本

邮件应该同时提供 HTML 和纯文本版本（有些用户禁用 HTML 邮件）：

```tsx
import { render } from "@react-email/render";

const html = await render(<VerifyEmail email="test@test.com" code="123456" />);
const text = await render(<VerifyEmail email="test@test.com" code="123456" />, {
  plainText: true,
});

// 发送时同时传 text 和 html
await resend.emails.send({
  from: "system@myapp.com",
  to: "user@gmail.com",
  subject: "验证邮箱",
  react: <VerifyEmail ... />,
  text,  // 纯文本备选
});
```

## 六、实用技巧

### 6.1 使用 PreviewProps 快速调试

不需要每次改代码才能看不同数据：

```tsx
export default function OrderEmail({ orderId, items, total }: Props) {
  // ...
}

// 开发预览时传入默认值
OrderEmail.PreviewProps = {
  orderId: "ORDER-12345",
  items: ["羽绒服 x1", "牛仔裤 x2"],
  total: 599.00,
};
```

### 6.2 封装通用组件（Footer、Header 等）

把重复的邮件元素抽离成组件，放在 `src/components/` 下：

```tsx
// components/header.tsx
export function EmailHeader({ logoUrl }: { logoUrl: string }) {
  return (
    <Section>
      <Img src={logoUrl} height="40" alt="Logo" />
    </Section>
  );
}

// 模板中使用
import { EmailHeader } from "../components/header";
```

> **注意**：如果组件放在 `templates` 目录下，用 `_components`（下划线前缀）命名，避免被扫描进侧边栏。

### 6.3 Tailwind 配置技巧

由于邮件客户端不支持 `rem` 单位，使用 Tailwind 的 `pixelBasedPreset`（可选）：

```tsx
<Tailwind
  config={{
    themes: {
      extend: {
        spacing: { ... },  // 建议用 px 值
      },
    },
  }}
>
```

### 6.4 生产环境 vs 开发环境切换图片路径

```tsx
const baseURL = process.env.NODE_ENV === "production"
  ? "https://cdn.myapp.com"
  : "";

export default function Email() {
  return (
    <Img src={`${baseURL}/static/logo.png`} />
  );
}
```

### 6.5 使用 CSS Module / Tailwind 的响应式

邮件最常用 600px 宽。使用 Container + max-w：

```tsx
<Container className="max-w-[600px]">
  {/* 内容 */}
</Container>
```

## 七、注意事项 & 踩坑指南

### 7.1 不是所有 CSS 都支持

邮件客户端能支持的 CSS 非常有限。以下是**不支持**的常见功能：

| 不支持 | 原因 |
|--------|------|
| `display: flex` / `display: grid` | 邮件端不支持，用 `<Row>` + `<Column>` 替代 |
| `rem` / `em` 单位 | 部分客户端不支持，用 `px` |
| CSS 变量 | 不支持 |
| JavaScript / React hooks | 邮件是静态 HTML，只能渲染快照，不能交互 |
| `hover:` 伪类 | 几乎所有邮件客户端都不支持 `:hover` |
| 外部样式表 / CSS Module | 只能内联样式或 Tailwind（Tailwind 组件会自动转内联） |
| `space-x-*` 等复杂选择器 | Tailwind 邮件版不支持复杂选择器 |
| `prose`（typography 插件） | 不支持 |
| `<video>` / `<audio>` | 不支持 |

### 7.2 Tailwind 组件的限制

1. **内部不能放 Context Provider**：`<Tailwind>` 内部不能使用 React Context（useContext 无效）。解决方案：把 Provider 移到 `<Tailwind>` 外面。
2. **不支持 `prose` 和复杂选择器**：类名查找策略限制，`space-x-*` 等也不支持。
3. **不是真 Tailwind**：`<Tailwind>` 实际上是**编译时**把类名转成内联样式，不是运行时跑 Tailwind 引擎。

### 7.3 `<Tailwind>` 不是一个 React Context

`<Tailwind>` 不会给子组件注入任何东西。如果你在子组件内部单独使用 `<Tailwind>`，实际上是两个完全独立的作用域。想让所有子组件都用同一套 Tailwind，只需要顶层一个 `<Tailwind>`。

### 7.4 预览服务器不等于线上可用

- 预览服务器只是开发工具，**不能直接用于生产发送**
- 预览时图片用 `/static/xxx.png` 能看，但真实邮件里必须用 CDN 绝对路径
- `email dev` 只在开发时用，生产部署不要依赖它

### 7.5 render() 在浏览器中运行需要 polyfill

如果在浏览器端调用 `render()`（非 Node.js 环境），Safari 需要 polyfill：

```bash
npm install web-streams-polyfill
```

```tsx
// 在入口文件中
import "web-streams-polyfill/polyfill";
```

> 服务端渲染（Next.js API Route、Node.js 后端）不需要这个。

### 7.6 生产环境安全（本项目的防护机制）

本项目在 `send-via-resend.ts` 中做了非生产环境保护：

```ts
const isProdEnv = process.env.VERCEL_ENV === "production";

// 非生产环境：邮件不发真实收件人，统一发到 Resend 测试邮箱
to: isProdEnv ? to : "delivered@resend.dev",
```

> 这意味着：本地开发、Vercel Preview 部署时，不会误发邮件给真实用户。

### 7.7 邮件模板中不要用 React Hooks

邮件模板**只是渲染函数**，最终会转成纯 HTML 字符串。任何 hooks（useState、useEffect、useContext 等）都无法工作。模板就是纯展示组件：

```tsx
// ✅ 正确：纯展示组件
export default function Email({ name }: { name: string }) {
  return <Text>你好 {name}</Text>;
}

// ❌ 错误：用了 useState，实际无效
export default function Email() {
  const [count, setCount] = useState(0);  // 不会工作
  return <Text>{count}</Text>;
}
```

### 7.8 测试建议

### 7.9 版本升级

如果你从 v4 升级到 v5+：

```bash
npx react-email@latest update
```

v5 的重大变化：
- `@react-email/components` 替代了旧的 `@react-email/button`、`@react-email/html` 等独立包

- `Preview` 组件移到 `@react-email/components` 中统一导出

### 7.10 邮件最佳实践清单

- [ ] 提供纯文本版本（方便无障碍访问）
- [ ] 600px 以内宽度（兼容小屏幕）
- [ ] 所有图片设 `alt` 属性（图片被阻止加载时也有文字）
- [ ] 关键信息用文字而非图片展示（CORS/代理可能屏蔽图片）
- [ ] 包含退订链接（大量发送的法律要求）
- [ ] 发件人域名配好 SPF/DKIM/DMARC（防止进垃圾箱）
- [ ] 在至少 3 种邮件客户端测试过
